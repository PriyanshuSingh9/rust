Noteworthy Language Mechanics & Invariants

1. Statements vs Expressions and the Unit Trap

Rust is an expression-oriented language. A trailing semicolon turns an expression into a statement, discarding its value and returning unit (). In functions returning concrete types (e.g. i32), trailing semicolons trigger compiler error E0308. 

fn double(x: i32) -> i32 {
    x * 2 // Evaluates to i32 and returns cleanly
    // x * 2; // Returns (), causing compiler error E0308
}

2. Dynamically Sized Types (DSTs) and Fat Pointers

Range slicing (a[1..4]) yields an unsized slice [T], not a fixed-size array [T; 3]. Because [T] has a dynamically determined size at runtime, it cannot exist as a bare local variable on the stack. Slices must live behind references (&[T]), which form a 16-byte fat pointer carrying a 64-bit data address and a 64-bit length. 

let a: [i32; 5] = [10, 20, 30, 40, 50];
let slice: &[i32] = &a[1..4]; // 16-byte fat pointer (ptr to a[1], len = 3)
let owned: Vec<i32> = a[1..4].to_vec(); // Explicit heap copy when caller owns memory

3. Shadowing vs In-Place Mutability

let mut x modifies existing memory while freezing the type. let x allocates a fresh stack variable, permitting type transformations while keeping the new binding immutable. 

let raw = "  42  ";
let parsed: u32 = raw.trim().parse().expect("valid integer"); // Clean type transformation

4. Algebraic Enums vs Discriminated Unions

Unlike TypeScript discriminated unions that depend on runtime property checks (type === "cash"), Rust enums are nominal tagged unions. Match statements enforce exhaustiveness at compile time; introducing a new variant immediately flags all unhandled branches across the codebase. 

enum Payment {
    Cash(u32),
    Card(String),
    Crypto(String),
}
